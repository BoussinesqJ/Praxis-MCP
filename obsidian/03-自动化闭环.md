## 断点续传 — Checkpointer（v3.0 新增）

> 子Agent执行过程中自动存档，支持中断恢复、trade_date 过期清理

### 设计原理

多团队联合分析（`/analyze <标的> all`）涉及 15 个子Agent，单次执行耗时长。断点续传确保：
- 网络中断后无需从头重跑
- 已完成的子Agent阶段结果被持久化
- 跨日自动过期（trade_date 与当前交易日不匹配时丢弃）

### 存档结构

```json
{
  "checkpoint_id": "cp-20260617-asrg-ethan",
  "trade_date": "2026-06-17",
  "team": "asrg",
  "member_id": "ethan",
  "phase": "member_prompt",
  "status": "completed",
  "output": { "...": "子Agent输出" },
  "timestamp": "2026-06-17T14:32:00+08:00"
}
```

### 流程

```
orchestrator(member_prompt, team="asrg", member_id="ethan")
    ↓
检查是否有有效断点（trade_date == today）
    ↓ 有 → 直接返回已存档结果
    ↓ 无 → 正常执行 → 执行完成后存档
返回结果
```

### Feature Flag

通过统一配置控制断点功能开关：

```yaml
# praxis_sdk/config.py
checkpointer:
  enabled: true           # 全局开关
  storage: "json"         # 存储格式（白盒可读）
  auto_expire: true       # trade_date 过期自动清理
```

> 配置文件：`praxis_sdk/core/checkpointer.py`

## 延迟反思机制（v3.0 新增）

> Step 0 反思 + Phase 1.5 Alpha 计算，在分析开始前注入历史经验

### quick-check Step 0 延迟反思

在每日快速检查（`/quick-check`）开始前，先回顾最近的决策复盘：

```
Step 0: 延迟反思
    ↓ review_tool(action="summary") — 获取待复盘决策摘要
    ↓ review_tool(action="fill") — 自动回填已到期的 5d/20d/60d 复盘
    ↓ 将反思结果注入后续检查上下文
Step 1: 正式检查流程
```

### daily-review Phase 1.5 Alpha 计算

在每日复盘报告生成过程中，插入 Alpha 追踪计算：

```
Phase 1: 收集数据
    ↓
Phase 1.5: Alpha 计算（v3.0 新增）
    ↓ agent_tracking(action="consensus", ticker=...) — 检查多Agent共识
    ↓ get_ai_tracking() — 获取 AI 建议命中率
    ↓ 计算相对基准的 Alpha 收益
Phase 2: 生成复盘报告
```

### 价值

- **延迟反思**：避免"分析惯性"，让今天的检查带着昨天的教训
- **Alpha 计算**：量化 AI 团队的真实贡献，而非仅看绝对收益

# PRAXIS 开发红线规则

> **违反任何一条红线，立即停止工作并道歉**

---

## 🔴 第一红线：推送必须获得确认

**规则**：每次推送到 GitHub 前，必须完成以下流程：

1. ✅ 执行安全审查脚本（`bash scripts/security_check.sh`）
2. ✅ 展示审查报告给用户
3. ✅ **等待用户明确说"推送"**
4. ✅ 用户确认后才执行 `git push`

**绝对禁止**：
- ❌ 不展示审查报告就推送
- ❌ 用户没说"推送"就推送
- ❌ 把"继续"、"好的"、"开始"等词理解为推送确认
- ❌ 在安全审查未通过时推送

**违反后果**：立即停止工作，向用户道歉

---

## 🟡 第二红线：个人信息保护

**规则**：推送到 GitHub 的代码必须清除所有个人信息

**检查项**：
- 三尺生 → 示例投资者
- sanchisheng → example
- 真实路径 → 占位符
- API Key → 环境变量

---

## 🟡 第三红线：数据安全

**规则**：敏感数据不得推送到 GitHub

**检查项**：
- 配置文件使用 `.example.json` 模板
- 实际配置文件在 `.gitignore` 中
- 大文件（>1MB）在 `.gitignore` 中
- 缓存目录在 `.gitignore` 中

---

## 执行方式

每次准备推送时，我会：

1. 展示安全审查报告
2. 列出待提交的变更
3. **等待你说"推送"**
4. 你确认后才执行推送

---

**此规则从现在开始生效，永不违反。**
